## 1. 系统架构

### 1.1 架构总览

采用**纯 Python 单体架构**，单进程运行，三层结构：

```
┌─────────────────────────────────────────────────────────────┐
│              表现层 — FastAPI 网页工作台（:8010）           │
│   templates/dashboard.html 单页应用（Tailwind + Tabler）     │
│   数据看板 | 数据大屏 | 每日经营数据 | 采集日志 | 凭证管理     │
│        │ JS fetch 轮询（8s）                                 │
└────────┼────────────────────────────────────────────────────┘
         │ 读写 SQLite / 调用调度器
         ▼
┌─────────────────────────────────────────────────────────────┐
│              核心层 — core/                                  │
│   scheduler(线程池并行)  task_manager(状态机)               │
│   credential_manager(加密+健康检查)  db  limiter            │
│        │                                                     │
│        ▼                                                     │
│   adapters/ — 适配器（统一接口 run(date)->CrawlerResult）    │
│   美团(异步多步) | 平台2(同步) | 平台3(同步) | ...           │
└────────┼────────────────────────────────────────────────────┘
         │ importlib 加载（原脚本零改动）
         ▼
┌─────────────────────────────────────────────────────────────┐
│              爬虫层 — crawlers/                              │
│   各平台原有 .py 脚本（保持不动）                            │
└─────────────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────────┐
│   SQLite(app.db)  +  credentials/credentials.enc(加密)       │
│   tasks 表 | daily_summary 表 | credentials 表               │
└─────────────────────────────────────────────────────────────┘
```

## 2. 适配器接口规范

### 2.1 核心数据结构

```python
# core/models.py
from dataclasses import dataclass, field
from typing import List, Dict, Optional

@dataclass
class Metric:
    """单个指标"""
    metric: str        # 指标名，如 "营业额"
    value: object      # 指标值，int/float/str
    unit: str = ""     # 单位，如 "元"/"单"

@dataclass
class CrawlerResult:
    """适配器统一返回结构"""
    platform: str                 # 平台名
    date: str                     # 采集日期 YYYY-MM-DD
    metrics: List[Metric]         # 标准化指标列表
    raw_file: Optional[str] = None  # 原始文件路径（如美团 Excel），便于排查
    extra: Dict = field(default_factory=dict)  # 扩展字段
```

### 2.2 适配器抽象基类

```python
# adapters/base.py
from abc import ABC, abstractmethod
from core.models import CrawlerResult
from core.task_manager import TaskManager  # 用于更新分步进度

class CrawlerAdapter(ABC):
    """所有平台适配器的基类"""

    @property
    @abstractmethod
    def platform_name(self) -> str:
        """平台标识名，如 'meituan'"""

    @abstractmethod
    def run(self, date: str) -> CrawlerResult:
        """执行采集，返回标准化结果。
        子类必须用 try/except 包裹原脚本调用，异常转为 CrawlerError，
        不要让异常冒泡到调度线程。"""

    @abstractmethod
    def check_credential(self) -> bool:
        """校验凭证是否有效，返回 True/False"""

    def update_progress(self, task_mgr: TaskManager, task_id: str,
                        step: str, progress: int):
        """供异步适配器（美团）更新分步进度"""
        task_mgr.update_step(task_id, step, progress)
```

### 2.3 同步适配器模板（适用平台2~5）

```python
# adapters/platform2_adapter.py （示意模板）
import importlib
from adapters.base import CrawlerAdapter
from core.models import CrawlerResult, Metric, CrawlerError

class Platform2Adapter(CrawlerAdapter):
    PLATFORM = "platform2"
    MODULE = "crawlers.platform2_crawler"   # 原脚本模块路径
    MAIN_FUNC = "run"                        # 原脚本主函数名（审查后确认）

    @property
    def platform_name(self) -> str:
        return self.PLATFORM

    def check_credential(self) -> bool:
        # 平台2若无需凭证，直接返回 True；否则读加密凭证并探测
        return True

    def run(self, date: str) -> CrawlerResult:
        try:
            mod = importlib.import_module(self.MODULE)
            raw = getattr(mod, self.MAIN_FUNC)(date)   # 直接拿原脚本返回对象
            metrics = self._normalize(raw)              # 转为 List[Metric]
            return CrawlerResult(platform=self.PLATFORM, date=date, metrics=metrics)
        except Exception as e:
            raise CrawlerError(self.PLATFORM, str(e))   # 转统一异常

    def _normalize(self, raw) -> list:
        """把原脚本返回的对象映射为 List[Metric]。
        具体映射规则在代码审查后确定。"""
        # 示例：raw = {"营业额": 12345.6, "订单数": 233}
        return [
            Metric("营业额", raw.get("营业额"), "元"),
            Metric("订单数", raw.get("订单数"), "单"),
        ]
```

### 2.4 异步适配器（美团）说明

美团适配器在 `run` 内部完成"提交→轮询→下载→解析→二次聚合"全流程，并通过 `update_progress` 更新分步进度。原脚本已封装此流程时，适配器主要职责是：
1. importlib 加载美团原脚本，调用其主函数（传入 date + 凭证）
2. 原脚本返回下载的 Excel 路径
3. 适配器用 openpyxl 解析 Excel，按列名映射提取指标
4. 多店铺时做聚合（求和/平均，视口径）
5. 返回 CrawlerResult

> mtgsig 处理：若原脚本已内置签名生成，适配器无需额外处理；若签名独立为 mtgsig.js，适配器通过 execjs 调用。具体方式待代码审查确认。

## 3. 数据流与状态机

### 3.1 完整数据流

```
用户选日期 + 点"采集"
   │
   ▼
[1] 调度器为每个平台创建 task（status=pending）写入 tasks 表
   │
   ▼
[2] 后台 daemon 线程启动 ThreadPoolExecutor，并行提交各适配器
   │
   ▼
[3] 每个适配器（线程内）：
   ├─ check_credential() → 失败则 task=failed，提示更新凭证
   ├─ importlib 加载原脚本，调用 run(date)
   │   ├─ 美团：提交→轮询→下载Excel→解析→聚合（每步 update_progress）
   │   └─ 其他：同步爬取→返回对象
   └─ 标准化为 CrawlerResult
   │
   ▼
[4] task_manager 更新 task 状态（running→success/failed）
   │
   ▼
[5] 成功的 task：metrics 序列化后 UPSERT 到 daily_summary（date+platform 唯一）
   │
   ▼
[6] 前端 JS 每 8 秒 fetch `/api/tasks/{date}` 轮询 tasks 表 → 刷新状态圆点/日志/统计
   │
   ▼
[7] 全部完成 → 数据看板从 daily_summary 读取，透视成宽表展示
```

### 3.2 任务状态机

```
        创建            开始执行          成功
  ┌─────────────┐   ┌──────────┐   ┌─────────┐
  │   pending   │──▶│ running  │──▶│ success │
  └─────────────┘   └──────────┘   └─────────┘
         │               │
         │               │ 失败/超时
         │               ▼
         │          ┌─────────┐
         │          │ failed  │
         │          └─────────┘
         │               │
         └───────────────┘
              手动重试
```

状态取值：`pending` / `running` / `success` / `failed`

## 4. 数据库表结构

### 4.1 tasks 表（任务状态）

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id           TEXT PRIMARY KEY,        -- UUID
    platform     TEXT NOT NULL,           -- 平台名
    date         TEXT NOT NULL,           -- 采集日期 YYYY-MM-DD
    venue        TEXT DEFAULT '',         -- 场地（冗余字段）
    status       TEXT NOT NULL DEFAULT 'pending',  -- pending/running/success/failed
    step         TEXT,                    -- 美团分步：submit/poll/download/parse
    progress     INTEGER DEFAULT 0,       -- 0-100
    started_at   TIMESTAMP,
    finished_at  TIMESTAMP,
    created_at   TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    retry_count  INTEGER DEFAULT 0,
    error_msg    TEXT
);
CREATE INDEX IF NOT EXISTS idx_tasks_date ON tasks(date);
CREATE INDEX IF NOT EXISTS idx_tasks_status ON tasks(status);
```

### 4.2 daily_summary 表（汇总数据，长表设计）

```sql
CREATE TABLE IF NOT EXISTS daily_summary (
    id            TEXT PRIMARY KEY,       -- UUID
    date          TEXT NOT NULL,          -- 日期 YYYY-MM-DD
    venue         TEXT NOT NULL,          -- 场地名（多场地）
    platform      TEXT NOT NULL,          -- 平台名
    metrics_json  TEXT NOT NULL,          -- 序列化的 List[Metric]
    raw_file      TEXT,                   -- 原始文件路径（可选）
    updated_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(date, venue, platform)         -- 同日同场地同平台唯一，重复采集覆盖
);
CREATE INDEX IF NOT EXISTS idx_summary_date ON daily_summary(date);
```

> **长表 vs 宽表**：采用长表（date+platform+metrics_json）存储，灵活适配各平台不同指标数量。前端展示时按 date 聚合，把各 platform 的 metrics 透视成宽表列。

### 4.3 credentials 表（凭证元信息）

```sql
CREATE TABLE IF NOT EXISTS credentials (
    platform        TEXT PRIMARY KEY,     -- 平台名
    encrypted_value TEXT NOT NULL,        -- Fernet 加密后的凭证
    status          TEXT DEFAULT 'unknown', -- active/expired/unknown
    last_check_at   TIMESTAMP,
    last_success_at TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

> 实现（已定稿）：凭证加密后直接存入 `credentials` 表 `encrypted_value` 字段；密钥保存于 `credentials/.fernet_key`。

### 4.4 SQLite 配置

- 启用 WAL 模式：`PRAGMA journal_mode=WAL;`（提升并发读写）
- 写事务用 `BEGIN IMMEDIATE` 避免写冲突
- 连接：每次操作新建连接（SQLite 轻量），或线程内复用连接

## 5. 并行调度设计

### 5.1 调度器（core/scheduler.py）

```python
# 伪代码
import threading
from concurrent.futures import ThreadPoolExecutor, as_completed
from core.task_manager import TaskManager
from adapters import build_adapters   # 工厂：返回所有适配器实例

class Scheduler:
    def __init__(self, task_mgr: TaskManager, max_workers: int = 5):
        self.task_mgr = task_mgr
        self.max_workers = max_workers

    def run_date(self, date: str):
        """后台执行某日全部平台采集（在 daemon 线程内调用）"""
        adapters = build_adapters()
        # 创建 task 记录
        task_ids = {
            a.platform_name: self.task_mgr.create(a.platform_name, date)
            for a in adapters
        }
        # 并行执行
        with ThreadPoolExecutor(max_workers=self.max_workers) as pool:
            futures = {
                pool.submit(self._run_one, a, date, task_ids[a.platform_name]): a.platform_name
                for a in adapters
            }
            for fut in as_completed(futures, timeout=600):
                platform = futures[fut]
                # 结果已在 _run_one 内处理，这里仅捕获未处理异常
                try:
                    fut.result()
                except Exception as e:
                    self.task_mgr.mark_failed(task_ids[platform], str(e))

    def _run_one(self, adapter, date, task_id):
        """单平台执行（含异常隔离）"""
        self.task_mgr.mark_running(task_id)
        try:
            if not adapter.check_credential():
                raise Exception("凭证失效，请更新")
            result = adapter.run(date)
            self.task_mgr.mark_success(task_id)
            self.task_mgr.save_summary(result)   # UPSERT daily_summary
        except Exception as e:
            self.task_mgr.mark_failed(task_id, str(e))
```

### 5.2 长任务后台线程模式（关键）

爬虫耗时数分钟，**不能在 FastAPI 请求线程中同步等待**。采用"daemon 后台线程 + 前端轮询"：

```python
# app_fastapi.py 采集接口（伪代码）
@app.post("/api/collect")
async def collect(start_date: str, end_date: str):
    if Scheduler.is_busy():
        raise HTTPException(409, "上次采集仍在进行中")
    scheduler.launch_background(start_date, end_date, adapters)  # daemon 线程
    return {"status": "started"}
```

```js
// templates/dashboard.html 前端轮询（伪代码）
async function refresh(){
  const [tasks, summary] = await Promise.all([
    fetch('/api/tasks/' + date).then(r => r.json()),
    fetch('/api/summary/' + date).then(r => r.json()),
  ]);
  updateSidebar(tasks); updateStatus(tasks); renderSummary(summary); renderLogs(tasks);
}
// 仅在看板页每 8 秒轮询一次，切换页面/离开标签页自动暂停
```

**要点**：
1. `Scheduler.launch_background()` 启动 daemon 线程（`daemon=True`），进程退出时自动结束
2. 接口立即返回，不阻塞页面；并发采集用 `ThreadPoolExecutor`（默认 12 并发）
3. 状态通过 SQLite 传递（线程安全），不依赖内存共享
4. `Scheduler._busy` 全局锁防止重复触发，冲突时返回 HTTP 409
5. 前端只读轮询 tasks 表，无锁竞争；后台线程持有线程池，与请求生命周期解耦

### 5.3 超时与重试

- 单平台总超时 600 秒（config.yaml `scheduler.single_task_timeout`）
- 调度器对临时网络错误按 `scheduler.max_retries` 重试并指数退避；凭证失效、映射错误、数据格式错误不重试
- 网络请求重试：`utils/http.py` 基于 urllib3 Retry（指数退避），仅对幂等 GET/HEAD/OPTIONS 自动重试
- 反爬异常（403）不重试，直接 failed
- 美团单步骤（轮询 downloadLink）超时 300 秒

### 5.4 熔断

- 单平台同日连续失败 3 次 → 标记熔断，跳过该平台
- 前端红色提示

## 6. 凭证管理设计

### 6.1 凭证分类与存储（账号密码中心）

各平台凭证字段不同，统一加密存储，适配器运行时读取注入（用户要求：账号密码集中管理，不写代码里）：

| 平台 | 凭证字段 | 当前状态 | 存储 |
|---|---|---|---|
| 美团 | Cookie + mtgsig + partner_id（多组合伙人） | 硬编码在脚本1，阶段4外置 | Fernet 加密 |
| 芸苔 | account + password | 参数传入（标杆），适配器注入 | Fernet 加密 |
| 其余平台 | 按需（账号密码/Cookie/Token） | 待审查 | Fernet 加密 |
| 配置 | 店铺ID、端点、DB密码 | — | config.yaml / .env |

> mtgsig 当前硬编码（非动态生成），阶段4 从脚本迁到凭证管理。芸苔 account/password 是标杆：参数传入，适配器从凭证管理读取注入 main，无需改脚本。

### 6.2 加密

- `cryptography.fernet.Fernet`
- 密钥：首次运行自动生成，保存于 `credentials/.fernet_key`
- 凭证 JSON 序列化 → Fernet 加密 → 密文存入 `credentials` 表 `encrypted_value` 字段
- 凭证管理页保存时加密，读取时解密注入适配器

### 6.3 健康检查

- 每日首次采集前，对每平台做轻量探测请求
- 失效则 status=expired，前端弹窗提示
- 记录 last_check_at / last_success_at

### 6.4 凭证更新流程

```
凭证管理页 → 用户填写各平台账号密码/Cookie → 测试连接 → 加密保存
   → 触发健康检查 → 成功则 status=active → 后续采集适配器自动读取注入
```

## 7. 前端页面设计

单页应用 `templates/dashboard.html`，Tailwind CSS + Tabler Icons（已本地化到 `static/`，离线可用），
左侧栏切换各功能区块，仅看板页轮询刷新：

### 7.1 数据看板

- 日期范围选择 + 「全部采集 / 刷新」操作栏，快捷键 `Ctrl+R` 刷新、`Ctrl+Enter` 采集
- 统计卡片：采集平台数 / 成功 / 失败 / 采集日期
- 汇总报表：按场地/负责人筛选，行=场地，列=各平台指标，支持导出 Excel（`/api/download/{date}`）
- 最近日志：最近 30 条任务日志，状态图标 + 错误信息

### 7.2 数据大屏

- 月度经营仪表盘：本月总收入 / 日均 / 完成率 / 月环比 / 单日收入
- 内地 TOP3、香港 TOP3、单日 TOP3、区域完成度（数据来自 `/api/dashboard/data`）
- 门店完成度：读取月度目标表（`data/targets/`，config.yaml `targets.file`）中「最终核定目标」为门店目标，按"本月累计 / 目标"计算完成率，绿色≥100% / 黄色70-99% / 红色<70%
- 区域完成度：按门店→区域映射（`data/targets/regions.json`，config.yaml `targets.store_regions_file`）聚合区域目标与实际（6 区域：香港/深圳/广州/江门/福州/东莞）
- 数据不完整时提示缺失日期

### 7.3 每日经营数据

- `GET /api/daily-operations?date=&venue=`：读取相邻累计快照并计算单日收入
- 月初首日使用累计值；普通日期严格要求目标日和前一自然日快照
- 返回完整性状态、缺失日期、缺失来源、门店平台拆分和历史口径提示
- 旧快照没有采集范围证明时标记为“历史口径未验证”
- 平台金额旁提供源数据 **追查**；全局入口位于门户顶部和后台侧边栏，入口目录来自 `GET /api/portal/platform-links`
- 后端只输出 `config.yaml` 白名单中的安全 HTTPS 页面，不向浏览器发送采集凭证；API 或本地文件来源显示无入口

### 7.4 采集日志

- 全量任务日志分页查看（每页 50 条），支持刷新

### 7.5 凭证管理（账号密码中心）

- 按平台折叠卡片：默认收起，点击展开（手风琴式，同时只展开一个，防误操作）
- 每平台表单：字段输入 + 显示/隐藏密码（👁）+ 保存 + 测试连接
- 状态徽章：已配置（active）/ 已失效（expired）/ 未配置；顶部统计已配置/待配置数
- 保存后实时更新徽章与统计，toast 提示；已保存凭证只返回字段配置状态，不向浏览器回填密钥；留空保存表示保留原值

## 8. 错误处理

| 场景 | 处理 |
|---|---|
| 原脚本抛异常 | 适配器 try/except 转 CrawlerError，task=failed，记录 error_msg |
| 凭证失效 | check_credential 返回 False，task=failed，提示更新 |
| 网络超时 | utils/http.py（urllib3 Retry）自动重试，仍失败则 task=failed |
| 反爬 403 | 不重试，task=failed，提示更新凭证 |
| Excel 解析失败 | 按列名映射容错，失败保留原文件，task=failed |
| 调度线程异常 | as_completed 捕获，task=failed |
