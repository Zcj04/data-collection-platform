# 09 · 部署与运行

迁移到新机器前，请先完成 [部署准备与放行条件](../deployment-readiness.md)；其中列出独立运行时、代理模板、数据迁移和回滚要求。

## 9.1 环境要求

| 项 | 要求 |
|----|------|
| 操作系统 | 当前在 Windows 10/11 本机开发与验证；尚未完成企业内网部署 |
| Python | 3.13.x（生产依赖按当前已验证版本固定） |
| 外部 MySQL | 本地/可达的 `store_mapping_db` 库（场地映射，只读）+ `.env` 配置密码 |
| 网络 | 可访问各平台后台（部分为公网 HTTPS） |

## 9.2 安装步骤

```powershell
# 1. 安装依赖
pip install -r requirements.txt

# 2. Playwright 浏览器（抖音登录 / 金山文档读取需要）
playwright install chromium

# 3. 配置环境变量
copy .env.example .env
#   编辑 .env：
#   MYSQL_PASSWORD=<本地MySQL密码>
#   ANALYST_API_KEY=<DeepSeek API Key>（AI 功能必需，不需要可留空）

# 4. 首次启动（自动建库建表、生成 credentials/.fernet_key）
$env:WORKBUDDY_DISABLE_AUTO_COLLECTION="1"
python -u app_fastapi.py
```

首次启动后，在本机浏览器访问 **http://localhost:8010/setup**，自行创建第一个超级管理员。初始化入口仅在用户表为空时有效，且不提供默认账号或默认密码。

以后从以下入口使用：

- 登录：**http://localhost:8010/login**
- 数据门户：**http://localhost:8010/portal**（根路径 `/` 同样打开门户）
- 管理后台：**http://localhost:8010/admin**

当前仍只监听 `127.0.0.1`；所有门户、后台和 API 数据均需要登录并通过权限校验。

### 内部账号权限

| 权限 | 能力 | 自动包含 |
|------|------|----------|
| `portal.view` | 查看企业数据门户 | — |
| `portal.download` | 下载门户汇总 Excel | `portal.view` |
| `boss_report.download` | 下载每月货款比老板报表及检查结果 | `portal.view` |
| `monitoring.view` | 查看数据监控、质量检查和同步状态 | — |
| `payment.view` | 查看货款原始数据、核算和出货明细 | — |
| `payment.manage` | 上传、修订货款及管理出货采集任务 | `payment.view` |
| `admin.access` | 进入管理后台并执行采集、凭证等管理操作 | `portal.view`，并覆盖上述业务读取权限 |
| `users.manage` | 创建、启停用户，改权限和数据范围，重置他人密码 | `admin.access`、`portal.view` |

拥有 `users.manage` 的管理员可在后台 **用户管理** 区创建账号、启停账号、调整权限、绑定全部或指定门店并重置其他用户密码。指定门店账号的主要看板、汇总、老板报表、监控和货款读取由服务端按范围过滤；系统会保护当前登录账号和最后一个有效用户管理员。

## 9.3 配置文件体系（三级优先：环境变量 > config.yaml > 代码默认值）

### .env（敏感信息）

| 变量 | 说明 |
|------|------|
| `MYSQL_HOST/PORT/USER/PASSWORD/DATABASE` | MySQL 连接（默认 localhost:3306/root/store_mapping_db） |
| `ANALYST_API_KEY` | LLM API Key（AI 分析师使用） |
| `ANALYST_BASE_URL` / `ANALYST_MODEL` | 默认 https://api.deepseek.com / deepseek-v4-flash |

### config.yaml 关键节

| 节 | 关键项 | 说明 |
|----|--------|------|
| `platforms.<name>` | base_url / timeout / metrics / task_timeout | 13 个平台端点与指标；美团另有轮询参数（poll_* 渐进退避）与 `task_timeout: 2400` |
| `scheduler` | max_workers=12 / single_task_timeout=600 / max_retries=3 | 采集并发、单平台超时和临时网络错误任务级重试（已实现） |
| `scheduler.auto_collect` | enabled=true / check_interval_seconds=30 / slots | 经营数据排程：每日 10:30 采集目标月 1 日至昨日，不采集当天；时间按 `Asia/Shanghai` 计算 |
| `mysql_pool` | pool_size=5 / max_overflow=3 | 连接池 |
| `http` | 超时/连接池/重试退避 | http_client 默认值 |
| `cache` | venue_map_ttl=3600 | 场地映射缓存 TTL |
| `mysql` | host/port/user/database | 密码留空走 .env |
| `database` | sqlite_path=data/app.db | SQLite 路径 |
| `targets` | file / store_regions_file | 月度目标表与区域映射 |
| `analyst` | provider/base_url/model/temperature/max_tool_rounds/timeout | AI 分析师 |

> 平台凭证（账号/密码/Cookie/mtgsig）**不落配置文件**，统一走网页「凭证管理」Fernet 加密存储。

## 9.4 运行方式

```powershell
# 唯一受支持的服务入口
python -u app_fastapi.py
# → uvicorn 监听 127.0.0.1:8010（仅本机）
# → 启动时自动：init_db 建表 + 清理遗留任务 + 启动经营数据/会员监控两套排程
# → 不要启用 uvicorn --workers 或 --reload
```

`app_fastapi.py` 会先选择依赖完整的 Python 运行时，并对 `data/app.db`
获取单进程锁。第二个 Web 进程会在改写任务状态或启动重复排程之前直接失败。

当前 Windows 主机使用用户级任务计划 `WorkBuddy-Data-Collection-8010`：用户登录后运行
`scripts/run_fastapi_service.ps1`。应用非正常退出后，启动器间隔 15 秒重启；如果启动器自身
退出，任务计划再间隔 1 分钟重试。任务以当前普通用户身份
运行，不保存登录密码，也不使用管理员或 SYSTEM 权限。应用日志写入
`data/logs/app_fastapi.log`，单文件 10 MB，保留 10 份轮转文件。

正式采集默认启用 `scheduler.process_isolation`：每个平台在独立 Python worker 中运行，达到平台超时或收到停止请求时，父进程会回收 worker 及其子进程，避免浏览器/网络调用卡住整个采集调度器。

```powershell
# 查看守护任务与运行状态
Get-ScheduledTask -TaskName "WorkBuddy-Data-Collection-8010"
Get-ScheduledTaskInfo -TaskName "WorkBuddy-Data-Collection-8010"

# 受控停止/启动（停止脚本会校验并结束占用 127.0.0.1:8010 的本项目子进程）
& .\scripts\stop_fastapi_service.ps1
Start-ScheduledTask -TaskName "WorkBuddy-Data-Collection-8010"
```

### 经营数据自动排程

- 排程默认启用，业务时区固定为 `Asia/Shanghai`。
- 每日 10:30 采集目标月份 1 日至昨日的正式累计数据；当天不自动采集，避免把未结束的当日进度当成正式数据。
- 服务在当日某个时段之后才启动时，会尝试补跑已错过时段；`scheduled_collection_runs.job_key` 保证同一时段不重复领取。
- 批次终态为 `success` / `partial` / `failed` / `expired`。管理后台和数据门户显示真实入库时间、13 源覆盖和下次排程；门户不显示平台敏感错误详情。
- 最近批次异常且尚未恢复时，管理后台显示站内待处理提示并跳转目标日期的质量中心；已有旧数据但最新任务失败/停止的平台也会进入 `retry_platforms`，后续最新任务成功后自动解除。
- 这套排程与“多金宝会员资产监控”的 10:00 昨日核对和 10:30–19:00 实时同步相互独立。

> 服务必须持续运行才能按时执行。生产初期请使用单 worker；失败事件会持久化到本地，配置 HTTPS webhook 后可向外部投递，但不会直接自动重跑。

首次配置完成后，应清除 `WORKBUDDY_DISABLE_AUTO_COLLECTION` 并以同一命令重启，
再确认经营采集和会员监控排程已经启动。

### 日常操作流程（数据专员视角）

1. **系统首次初始化**：在本机 `/setup` 创建超级管理员。
2. **账号准备**：超级管理员登录后台，在用户管理区为同事创建账号并授予最小必要权限。
3. **凭证准备**：凭证管理页逐平台录入账号/密码（美团录 Cookie+mtgsig+partner_id）。
4. **自动采集**：保持服务运行，由 10:30 排程抓取目标月 1 日至昨日；在后台确认批次状态、范围、13 源覆盖、入库时间和下次运行。
5. **失败兜底**：看到自动采集待处理提示后进入质量中心，核对 `retry_platforms` 并手动补采缺失/失败平台；凭证失效时先在凭证管理页更新。
6. **数据消费**：获授权用户登录门户，查看数据和新鲜度；有 `portal.download` 时可导出 Excel。仅 `portal.view` 不能触发采集。

## 9.7 常见问题（FAQ）

| 现象 | 原因与处理 |
|------|-----------|
| 美团采集超时/失败 | `mtgsig` 为硬编码签名含时间戳，会过期；从浏览器抓包更新凭证管理页的 mtgsig 与 Cookie（见 docs/爬虫代码审查报告.md） |
| 抖音反复要求登录 | Cookie 过期；凭证管理页填账号密码后系统会用 Playwright 有头自动登录重取（遇滑块需人工） |
| 芸苔登录提示验证码 | 平台风控；人工到 rapa.vip 官网登录一次过验证 |
| 场地匹配失败/unmatched | MySQL `company_organizational_structure` 对应平台列未配置该店铺名；在 MySQL 侧补充映射 |
| MySQL 连接异常 | 检查 .env MYSQL_PASSWORD 与 MySQL 服务状态（外部 MySQL 不可用时，采集链路中所有需要映射的平台会失败） |
| 大屏“请先采集数据” | daily_summary 无当日（或区间）数据；先触发采集 |
| 服务重启后任务全变 failed | 启动时自动清理僵尸 running 任务的设计行为（error_msg=服务重启，任务中断） |
| 自动采集未按时运行 | 确认 Web 服务当时持续运行且 `scheduler.auto_collect.enabled=true`；当日重启会检查已错过时段 |
| 自动批次显示 partial/failed/expired | 点击自动采集卡“查看并补采”；质量中心会同时列出完全缺失和已有旧数据但最新任务失败/停止的平台，检查凭证/验证码、MySQL 映射、八达通 E 盘 CSV 和货款 C 盘 Excel 路径后，由管理员手动补采 |
| 没有收到自动采集失败消息 | 检查 `.env` 的 `WORKBUDDY_ALERT_WEBHOOK_URL`；留空时告警只写入本地 `alert_events`，管理员需登录后台查看 |
| AI 功能报 401 | .env ANALYST_API_KEY 未配置/失效 |

## 9.8 安全注意事项

- 服务默认监听 `127.0.0.1:8010`；旧 `/api/*`、`/api/portal/*` 和 `/api/admin/*` 均执行相同的数据库 Session 与权限校验，凭证读取接口只返回配置状态，不返回解密后的密钥。
- Session Cookie 名为 `workbuddy_session`，HttpOnly、SameSite=Strict，有效期 12 小时；服务端数据库只保存随机令牌的 SHA-256 哈希。已登录的写请求还需通过 CSRF token 和同源来源校验。
- 如通过反向代理开放远程访问，必须使用 HTTPS，并让应用正确识别 HTTPS 请求；此时 Cookie 才会带 `Secure`。同时继续限制内网访问范围，不应直接暴露到公网。
- `credentials/.fernet_key` 为凭证解密主密钥，禁止提交版本库/外发；`data/app.db` 还保存用户密码哈希、权限和有效 Session，二者应一并安全备份并限制文件权限。
- `.env`（含 MySQL 密码与 API Key）禁止提交版本库
- 导出的经营 Excel 含敏感营收数据，注意分发范围
- 更多威胁模型见 `.workbuddy/output/安全设计.md`（STRIDE 17 条威胁与缓解）

## 9.9 已知技术债与演进方向

**技术债**：
- 主要场地映射查询已接入 MySQL 连接池（utils/mysql_pool），报表及少数复杂查询仍待迁移
- `scheduler.max_retries` 已实现，但仅重试超时、连接、429 和部分 5xx 临时错误；凭证、验证码、映射和格式错误仍需管理员介入
- http_client 工具未被爬虫普遍采用
- 经营数据排程当前与 Web 进程同生命周期，尚未拆分为独立任务服务；上线初期由单 worker 和 Windows 任务计划守护
- 自动采集异常可写入外部 HTTPS webhook，但尚未提供钉钉/企业微信专用消息格式；异常不会直接自动重跑
- 部分设计文档仍写 Streamlit/8501（实际已迁移 FastAPI/8010）

**规划中**（见 overview.md）：
- 短期 v3.x：HTTPS/反向代理部署、继续覆盖新增接口的账号—门店范围过滤、WebSocket 实时进度推送、采集进度可视化
- 中期 v2.2：PostgreSQL 迁移评估、独立任务进程/外部调度器、环比同比图表、企业微信/钉钉告警
- 长期 v3.0：微服务拆分、数据仓库 + BI、自动异常检测修复、多租户
