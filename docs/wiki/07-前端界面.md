# 07 · 前端界面：数据门户与管理后台

当前前端保持原生 HTML/JavaScript，不依赖 Vue/React：`templates/login.html` 承载首次初始化与登录，`templates/portal.html` 是数据门户，`templates/dashboard.html` 是管理工作台；页面共用本地静态资源和现有后端计算口径。

## 7.1 技术栈

| 维度 | 选型 |
|------|------|
| 框架 | 原生 JS，单页多 section |
| 样式 | 本地 Tailwind 运行时 + `workbench.css` 设计 Token/组件样式 |
| 图标 | Tabler Icons（**本地化** `/static/vendor/tabler-icons/`，`ti-*` 类名；v2.1 起全面替代 emoji） |
| 数据交互 | 原生 `fetch` + `AbortController`（可中断轮询） |
| 身份与权限 | HttpOnly 数据库 Session + 八项模块权限 + 同源/CSRF 校验 |
| 响应式 | 桌面左侧栏；≤768px 顶栏和抽屉；固定侧栏内容在窄屏自动堆叠 |
| 可访问性 | 跳转主内容、统一焦点环、全局 live-region、抽屉键盘控制、减少动画偏好 |

> 静态资源已从外网 CDN 迁移到本地 `static/`（v2.1），离线可用。

## 7.2 双入口

- 首次启动访问 `/setup`，仅可在本机创建第一个超级管理员；系统不提供默认账号或默认密码。
- 以后统一访问 `/login`。登录成功后，有 `admin.access` 的账号进入 `/admin`，全量门户账号进入 `/portal`，绑定指定门店范围的账号默认进入 `/store`。
- `/`、`/portal`：经营总览、大屏简要、每日经营数据、门店汇总和预测；需要 `portal.view`，下载还需 `portal.download`。
- `/store`：门店负责人专用入口；沿用只读门户组件，但明确显示“我的门店经营数据”，所有读取由服务端按绑定门店过滤。
- 门户会按专业权限显示附加板块：`boss_report.download` 显示“下载老板报表”，`monitoring.view` 显示“数据监控”，`payment.view` 显示“货款数据”；上传、修订和同步等写操作不会出现在只读门户。
- `/admin`：10 区块数据采集工作台；需要 `admin.access`，其中用户管理区还需 `users.manage`。
- 后台继续兼容原 `/api/*` 调用，同时提供 `/api/admin/*` 分组别名；两套路径均由服务端执行相同的身份和权限校验。老板报表、数据监控、货款查看和货款管理已拆分为独立 API 权限，管理后台页面入口仍由 `admin.access` 控制。
- 当前服务仍只监听 `127.0.0.1`，仅本机可以连接。

门户使用的基础接口为 `/api/portal/summary/{date}`、`dashboard/status`、`dashboard/data`、`daily-operations`、`platform-links`、`analyst/forecast` 和 `download/{date}`；具有对应专业权限的账号还可在门户读取老板报表、货款数据和会员监控。货款上传、修订、同步、质量补采、日志和凭证等写入或管理操作仍留在管理侧。

八项权限的依赖关系为：`portal.download`、`boss_report.download` 自动包含 `portal.view`；`payment.manage` 自动包含 `payment.view`；`admin.access` 自动覆盖业务模块权限并包含 `portal.view`；`users.manage` 自动包含 `admin.access` 和 `portal.view`。`users.manage` 仍需显式授予，不能由 `admin.access` 推导。

## 7.3 管理后台布局与导航

左侧固定侧边栏（实时平台状态圆点 + 单跑按钮）+ 右侧主内容区；移动端抽屉式。侧边栏及移动抽屉都提供 **源平台入口**，门户则在顶部提供同一入口；点击后打开统一的平台目录弹窗。

**10 大功能区块**（`showSection(name)` 切换，URL hash 保留当前区块）：

| 区块 | 图标 | section 容器 | 功能 |
|------|------|--------------|------|
| 数据看板 | ti-layout-dashboard | sec-dashboard（默认） | 日期范围选择 + 全部采集 + 自动采集状态/站内异常提示 + 汇总表 + 导出 Excel |
| 数据大屏 | ti-chart-bar | sec-bigscreen | 月度经营仪表盘 |
| 每日经营数据 | ti-calendar-stats | sec-daily | 日期/门店筛选、单日收入差值、平台拆分与缺失提示 |
| AI 分析师 | ti-robot | sec-analyst | SSE 流式问答 + 历史会话 |
| 预测分析 | ti-chart-line | sec-forecast | 完成率推演 + 趋势 + 异常检测 |
| 数据监控 | ti-radar | sec-monitoring | 会员资产流水、同步与复核提醒 |
| 采集日志 | ti-activity | sec-logs | 按日期查日志分页，并显示数据健康检查 |
| 凭证管理 | ti-key | sec-credentials | 按平台折叠卡片 + 密码可见切换 |
| 货款数据 | ti-wallet | sec-paymentdata | 年月日历、Excel 导入与按日明细 |
| 用户管理 | ti-users | sec-users | 创建账号、启停、手动填写职位、修改八项权限和数据范围、重置或永久删除他人账号；权限明细可折叠，门店范围从标准清单多选，并按职位分组 |

## 7.4 各区块细节

1. **数据看板**：主表格（行=日期/场地，列=各平台指标+状态点+操作）；侧边栏平台状态卡（成功/运行中/失败/空闲四色圆点+脉冲动画）；自动采集卡展示上次/下次排程和数据覆盖。最近批次为 `partial` / `failed` / `expired` 且未恢复时，卡内出现 **查看并补采**，点击只会带入业务日期并跳转采集日志的数据健康检查，不会直接发送采集请求；`Ctrl+Enter` 仅在看板且焦点不在输入控件时触发采集，不覆盖浏览器 `Ctrl+R`。
2. **数据大屏**：总收入/完成率/内地与香港 TOP3/单日 TOP3/门店完成度/区域完成度；完成度颜色 绿≥100% / 黄 70–99% / 红<70%，门店按完成率升序排列。
3. **每日经营数据**：严格使用目标日与前一自然日的月累计快照计算；数据缺失、采集范围未知或平台缺行时显示状态，不把缺失当作0。每个平台金额旁显示 **追查**，有安全入口时在新标签页打开对应源平台，没有网页入口时显示 **无入口**。
4. **凭证管理**：手风琴式折叠卡片（同时只展开一个防误操作）；密码框 👁 显示/隐藏；已保存凭证仅显示配置状态，留空保存保留原值；状态徽章（已配置/已失效/未配置）+ 顶部统计。
5. **AI 分析师**：按 SSE 事件渲染（tool 事件显示工具调用指示、delta 增量输出）；左侧历史会话列表。
6. **用户管理**：仅 `users.manage` 账号显示导航和内容；可创建账号、启停、手动设置职位、调整权限和数据范围并重置其他用户密码。职位只用于用户列表分组，不自动改变权限；未填写的账号归入“未设置职位”。删除按钮会永久删除其他账号并撤销其会话，删除前必须确认；不能删除当前登录账号或最后一个有效用户管理员。权限明细默认收起；选择“指定门店”后才解禁门店输入框，点击后以多选下拉框选择系统标准门店，在营门店置顶。主要看板、汇总、老板报表、监控和货款读取已在服务端过滤；后续继续覆盖新增接口。服务端负责权限依赖、当前账号保护和最后一个有效用户管理员保护，隐藏前端控件不是安全边界。
7. **采集日志与数据健康**：日志页同时加载任务记录和质量报告；每月 1 号跳过前一日比较，其他日期严格比较自然日前一天的累计值，后一天更少即显示待处理项；补采按钮使用 `retry_platforms`（缺失 + 最新失败/停止平台）。

后台启动时先调用 `/api/auth/me` 取得当前用户、权限和 CSRF token，并在侧边栏/移动端显示当前账号及退出按钮。前端统一包装同源 `fetch`：写请求自动添加 `X-CSRF-Token`，收到 401 时跳转 `/login`。Session Cookie 为 HttpOnly，前端 JavaScript 不读取会话令牌。

## 7.5 管理后台 → 后端 API 调用映射

| 前端动作 | API | 时机 |
|----------|-----|------|
| 登录状态初始化 | `GET /api/auth/me` | 页面启动时获取当前用户、权限、CSRF token 和到期时间 |
| 退出登录 | `POST /api/auth/logout` | 侧边栏或移动端账号区触发；删除当前 Session |
| 用户列表 | `GET /api/admin/users` | 激活用户管理区时；需要 `users.manage` |
| 门店清单 | `GET /api/admin/venues` | 激活用户管理区时；用于数据范围多选 |
| 创建用户 | `POST /api/admin/users` | 提交账号、姓名、密码和权限 |
| 更新用户 | `PATCH /api/admin/users/{id}` | 保存权限、姓名或启停状态 |
| 删除用户 | `DELETE /api/admin/users/{id}` | 确认后永久删除其他账号并撤销其 Session |
| 重置他人密码 | `POST /api/admin/users/{id}/reset-password` | 用户列表操作；重置后目标用户 Session 失效 |
| `refresh()` | `GET /api/tasks/{date}` + `GET /api/summary/{date}` + `GET /api/portal/collection/status?date=`（Promise.all） | **8 秒轮询**；刷新侧边栏、汇总、日志、自动采集卡和站内异常提示 |
| 全部采集 | `POST /api/collect` | 按钮触发；409 提示"上次采集仍在进行中" |
| `runSingle(platform)` | `POST /api/collect/single` | 侧边栏失败平台 ▶ 按钮 |
| `stopTask(taskId)` | `POST /api/tasks/stop/{taskId}` | 带 confirm 确认 |
| `refreshLogs()` | `GET /api/logs/{date}` + `GET /api/quality/{date}` | 日志页加载任务日志和数据健康，时间倒序分页 |
| 大屏加载 | `GET /api/dashboard/status` + `GET /api/dashboard/data` | 大屏页激活 |
| 每日经营数据 | `GET /api/daily-operations?date=&venue=` | 日期/门店筛选，读取单日差值与完整性状态 |
| `loadPlatformLinks()` | `GET /api/portal/platform-links` | 页面启动时读取源平台目录；全局弹窗和每日经营“追查”共用同一白名单 |
| `loadCredStatus()` | `GET /api/credentials` | 凭证页加载/保存后 |
| 凭证状态 | `GET /api/credentials/{platform}` | 展开某平台卡片时（不返回密钥） |
| 凭证保存 | `POST /api/credentials/{platform}` | 表单提交 |
| AI 配置/会话 | `GET /api/analyst/config`、`GET /api/analyst/sessions`、`GET /api/analyst/session/{id}` | 分析师页初始化 |
| AI 提问 | `POST /api/analyst/ask/stream` | SSE 流式接收 |
| 预测分析 | `GET /api/analyst/forecast` + `GET /api/analyst/forecast/anomaly`（Promise.all） | 预测页加载 |
| 汇总导出 | `GET /api/download/{date}` | 看板导出按钮 |
| 质量检查 | `GET /api/quality/{date}` | 采集日志加载；返回 `missing_platforms`、`retry_platforms`、前一日对比和问题清单 |
| 补采缺失/失败平台 | `POST /api/quality/collect-missing` | 管理员确认后触发；优先使用 `retry_platforms` |

## 7.6 通知与反馈

- Toast 为 `<body>` 直属全局层，在所有功能区可见；成功/错误/信息三态均有辅助技术播报语义
- 任务状态徽章与平台状态圆点实时反映 tasks 表状态（8s 轮询驱动）
- 自动采集异常提示属于站内反馈，不是持久化消息中心；当前没有钉钉、企业微信、邮件通知，也不会直接自动重跑

## 7.7 视觉与回归约定

- 深色运营侧栏 + 浅色数据工作区；品牌蓝只用于主操作/选中态，红黄绿只表达业务状态。
- 10 个功能区统一使用“图标、标题、口径说明、页面操作”的页头骨架。
- 看板 KPI、缺失日期、区域卡片、AI 历史栏和预测异常栏都有移动/平板降级规则。
- `tests/test_ui_contract.py` 检查 section 标题、静态 ID、全局 Toast、响应式/焦点规则和本地图标完整性。
- UI 交付前至少检查 1440px 桌面、约 1024px 平板与 ≤500px 小屏视图。
