# 01 · 项目概览

## 1. 项目定位

**数据采集平台**是面向数据专员（单用户）的 Windows 单机工具，定位为「多平台经营数据的采集中枢 + 汇总看板」，用于替代原先的手工八爪鱼 RPA + 散装爬虫流程。

- **上游**：13 个第三方平台/本地数据源（游乐场门店的收款、投币、积分等经营数据）
- **下游**：数据专员日常消费（看板、Excel 分发、AI 问答）

### 解决的核心痛点

| 痛点 | 方案 |
|------|------|
| 每天重复手工采集 1~2 小时 | 一键并行采集，耗时压缩到 ≤10 分钟 |
| 多平台流程割裂、状态不可见 | 统一看板 + 实时任务状态 + 失败重试 |
| 凭证散落硬编码在脚本里 | Fernet 加密集中存储，网页凭证管理页维护 |
| 单平台失败无感知 | 任务状态机 + 日志 + 单平台一键重跑 |

## 3. 技术栈

| 类别 | 选型 |
|------|------|
| 语言 | Python 3.8+（推荐 3.13；`__pycache__` 中同时存在 3.8/3.10/3.13 编译产物） |
| Web 框架 | FastAPI + uvicorn（端口 8010） |
| 前端 | 原生 HTML/JS 单页应用，Tailwind CSS + Tabler Icons（均已本地化到 `static/`） |
| 并发 | `ThreadPoolExecutor`（12 线程）+ daemon 后台线程 |
| 本地存储 | SQLite（WAL 模式），`data/app.db` |
| 外部数据库 | MySQL `store_mapping_db`（**只读**，店铺名→场地映射），pymysql |
| 加密 | cryptography Fernet（AES-128-CBC + HMAC-SHA256） |
| 数据处理 | pandas / numpy / openpyxl |
| 浏览器自动化 | Playwright（抖音登录、金山文档读取） |
| LLM | openai SDK（OpenAI 兼容接口，默认 DeepSeek `deepseek-v4-flash`） |
| 配置 | YAML（`config.yaml`）+ python-dotenv（`.env`，环境变量优先） |

生产依赖及已验证版本见 `requirements.txt`；测试环境在此基础上安装 `requirements-dev.txt`。

## 6. 核心数据流

```
采集流（正向）：
  前端「全部采集」→ POST /api/collect
    → Scheduler.launch_background（daemon 线程，类级锁互斥）
    → ThreadPoolExecutor(12) 并行 13 个适配器
    → 适配器：CredentialManager 解密凭证 → importlib 加载爬虫 → 注入凭证
    → 爬虫 main()：登录平台 → 拉取数据 → MySQL 映射场地 → 返回 [{场地, 指标...}]
    → TaskManager.save_summary：UPSERT daily_summary（键 date+venue+platform）

消费流（反向）：
  数据看板：GET /api/summary/{date} → daily_summary + report_summary.main() 透视宽表
  数据大屏：GET /api/dashboard/data → 累计差分还原单日 + 目标完成度计算
  每日经营数据：GET /api/daily-operations → 相邻月累计快照差分 + 缺失状态
  AI 分析师：LLM 工具调用 → query_summary/dashboard_snapshot/forecast/anomaly
```

## 7. 关键设计决策

| 决策 | 内容 | 理由 |
|------|------|------|
| 爬虫零改动 | `crawlers/` 保留原始脚本，由 `adapters/` 层通过 `importlib` 动态加载 | 避免重写引入回归风险，老脚本久经生产验证 |
| 单体架构 | FastAPI + SQLite 单进程单机部署 | 单用户桌面工具，无多租户/云端需求，0 元/月运维成本 |
| 线程而非协程 | 爬虫为同步阻塞 requests，用线程池并行 | 原始脚本零改动的前提下获得并行能力 |
| 独立超时 | 每平台独立 deadline（美团 2400s，其余默认 600s） | 慢平台（美团轮询下载）不阻塞其他平台结果落库 |
| LLM 不算数 | 所有数字由 Python 确定性计算，LLM 只做翻译/解释 | 避免大模型幻觉导致财务数字错误 |
| 累计口径存储 | daily_summary 存「当月累计值」，单日值由相邻采集日差分还原 | 契合平台后台报表原生口径 |
