# 新增平台：油菜花（某省会城市门店）需求文档 + 技术方案

> 状态：待确认
> 平台入口：http://86450002.v004.youcaihua.net:88/admin/#/finance/daily-sttlement-record（每日结算一览 / 收银一览）
> 调研方式：已下载并逆向前端 UmiJS 包（umi.c3d0f006.js + 登录页/结算页 chunk），接口参数与响应结构均已确认。

## 1. 平台接口分析结论（已核实）

### 1.1 登录

| 项目 | 内容 |
|---|---|
| 接口 | `POST /DTOWebLogin` |
| 凭证传递 | **URL query 参数**：`username`、`password`（明文的 **Base64** 编码，即 `btoa(明文)`）、`ValidCode` |
| 鉴权方式 | 服务端 **会话 Cookie**（登录成功后 Cookie 随响应下发，后续请求同源自动携带） |
| 验证码 | `POST /GetLoginValidCode` 返回 `Data.ValidCode`（Base64 JPG 图片验证码）。**条件性出现**：前端仅在该接口返回非空 ValidCode 时才显示验证码输入框；登录报错码 8023/8024 表示需要验证码/刷新验证码 |

登录请求示例：
```
POST /DTOWebLogin?username=xxx&password=MTIzNDU2&ValidCode=
```

### 1.2 数据接口（用户指定）

| 项目 | 内容 |
|---|---|
| 接口 | `POST /Finance/DTOGetCashSumByEmp` |
| 请求体 | JSON：`{"StartPeriod": "YYYY-MM-DD", "EndPeriod": "YYYY-MM-DD", "DateType": 99}`（前端写死 `DateType: 99`，即自定义账期） |
| 响应 | `Data.rows`：`[{EmpName: "操作员", PayDetails: [{PayType, PayMethod, PayedMoney}]}]`<br>`Data.headers`：`[{PayType, PayMethod}]`（动态列，页面按此生成表格列）<br>`Data.footer`：合计行；`Data.TotalSys`：总金额 |
| 维度 | **按操作员（EmpName）× 支付方式（PayType × PayMethod）的收银现金汇总** |

### 1.3 关键点

- 子域名 `86450002` 即**门店商场编码（mallCode）**，一个子域名 = 一个商场账号，登录页会显示"门店名称(编码)"。
- 接口为 **HTTP 明文**（非 HTTPS），平台"人工入口"白名单只允许 HTTPS，因此该平台在前端不会显示入口链接（kind=unavailable），不影响采集。
- 采集系统现有 `_SyncAdapter` 模式完全适用（账号密码 → 凭证管理注入 → main() 返回场地维度字典列表）。

## 2. 需求确认（需你答复）

1. **平台标识与名称**：建议 `platform_id = youcaihua`，显示名「油菜花」。是否同意？
2. **门店/账号范围**：该账号（86450002）是只有某省会城市一家店，还是后续还会开更多油菜花子域名账号？这决定爬虫是"单店返回固定场地"还是"多账号循环"。
3. **指标口径**：接口返回的是「操作员 × 支付方式」的收款汇总。你需要的指标列是什么？例如：
   - 简单口径：`油菜花收款`（所有 PayMethod 合计）+ 可能拆 `油菜花现金` / `油菜花非现金`
   - PayType / PayMethod 的实际取值（如"现金""微信""支付宝"）需要登录后抓一次真实数据确认，届时再定映射。
4. **门店映射**：某省会城市门店在 MySQL `company_organizational_structure` 里如何对应？
   - 单店方案：config 里直接配置 `venue: "某省会城市XX店"`，无需新列；
   - 或新增 `youcaihua` 映射列（与其他平台一致，操作员名→场地）。
5. **凭证**：请在平台「凭证管理」里新增 `youcaihua` 的账号/密码，或直接发我账号密码（仅用于本地凭证加密存储）。
6. **验证码风险**：如该账号登录强制图片验证码，纯 requests 无法自动登录。可选方案：
   - a) 先试登录，如未启用验证码则无问题（常见情况）；
   - b) 强制验证码时：用简单 OCR 识别（成功率不保证）；
   - c) 降级方案：手动登录浏览器后复制 Cookie 到凭证管理（像美团 Cookie 模式）。

## 3. 实施方案（确认后执行）

1. `crawlers/youcaihua_crawler.py`（单文件自包含，风格对齐 `leyaoyao_crawler.py`）：
   - `create_session()`：重试会话 + UA + Referer；
   - `login(session, username, password)`：Base64 编码密码，query 传参，校验响应 `success`/`ResponseStatus`；
   - `get_cash_sum(session, start, end)`：POST JSON `{StartPeriod, EndPeriod, DateType: 99}`，解析 `Data.rows`；
   - 金额聚合 → 场地维度 `{"场地": ..., "油菜花收款": ...}` 返回；未匹配项打印告警；
   - `main(start_date, end_date, username=None, password=None)`，支持环境变量 `YOUCAIHUA_USERNAME/YOUCAIHUA_PASSWORD`。
2. `adapters/all_adapters.py`：新增 `YoucaihuaAdapter(_SyncAdapter)`（PLATFORM="youcaihua", MODULE="crawlers.youcaihua_crawler"）。
3. `adapters/factory.py`：注册进 `build_adapters()`。
4. `config.yaml`：`platforms.youcaihua`（name: 油菜花、type: sync、base_url、metrics）。
5. 凭证管理界面自动出现新平台（沿用现有 CredentialManager，无需额外改动——确认后我会核对前端平台列表是否由 factory 驱动）。
6. 测试：先跑真实登录 + 拉一天数据 → 核对 PayType/PayMethod 取值 → 定指标列 → 再跑日期区间验证。
7. 按惯例：**不主动重启服务**，完成后由你自行重启验证。

## 4. 待定风险

- 验证码是否强制（见 2.6）。
- `DateType: 99` 与账期口径：结算页默认账期为"本月1日～月末"，跨日区间接口是否按日拆分需实测（若只返回区间汇总，则与"日报"口径的对接方式需再讨论，参考兑币机的累计值处理）。
