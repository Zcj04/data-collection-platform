# 数据监控接入设计

## 当前能力

“数据监控”页面已经与经营数据采集任务解耦。页面统一读取 `monitor_events`，数据库中没有真实事件且从未成功同步时才展示带有“演示数据”标识的模拟流水。多金宝会员储值爬虫已经接入，可在页面点击“同步储值数据”；会员积分爬虫仍待后续接入。

当前监控范围：

- 会员积分：增加、兑换、人工调整
- 会员储值：充值、赠送、消费、退款、其他调整
- 风险提醒：大额积分调整、大额充值、大额赠送、大额退款或调整
- 查询筛选：近 7/14/30 天、资产类型、门店
- 隐私处理：多金宝会员标识入库前即单向伪名化，不保存姓名、手机号和头像

## 多金宝储值爬虫

实现文件：`crawlers/duojinbao_store_value_crawler.py`。

- 复用凭证管理中的多金宝单一采集账号，不在源码中保存账号密码。
- 登录后读取账号可见门店并切换门店上下文。
- 日期范围按最多 5 天拆分，接口使用 `pageIndex/pageSize` 分页。
- 严格按实测响应契约 `data.items/total/pages` 解析；结构异常不会被误判为零记录。
- 每条记录用 `actualBenefit == accountEndBalance - accountInitialBalance` 对账。
- 平台 `accountBenefitId` 实测可能重复，因此使用门店、账户、时间、金额、订单和类型的组合哈希作为幂等键。
- 分页总数、空页、重复页和最大页数都有完整性检查。
- 账号与门店分层隔离错误，允许成功门店入库并将运行标记为“部分完成”。
- 原始追溯字段采用最小集合，不写入姓名、手机号、头像或登录信息。

后台同步入口：

- `POST /api/monitoring/sync?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`
- `GET /api/monitoring/sync/status`

## 爬虫写入契约

其他监控爬虫完成后，将每一笔变更转换成下面的字典，并调用 `core.monitoring.save_monitor_events(events)`：

```python
from core.monitoring import save_monitor_events

save_monitor_events([
    {
        "source": "member_system",
        "external_id": "平台原始流水号-必须稳定",
        "occurred_at": "2026-08-19T14:32:00",
        "venue": "深圳F店",
        "member_ref": "来源侧稳定会员ID的伪名值",
        "event_type": "balance_recharge",
        "amount": 500.00,
        "balance_after": 688.00,
        "operator": "收银台充值",
        "raw": {"保留平台原始字段": "便于追溯"},
    }
])
```

`source + external_id` 是幂等键。爬虫重复抓取同一笔流水时会更新原记录，不会重复累计。如果源平台没有流水号，写入服务会根据事件关键字段生成稳定 ID，但优先使用源平台提供的 ID。

## 标准事件类型

| event_type | 含义 | amount 方向 | 单位 |
| --- | --- | --- | --- |
| `points_earn` | 积分增加 | 正数 | 积分 |
| `points_redeem` | 积分兑换 | 负数 | 积分 |
| `points_adjust` | 人工调整 | 增加为正，扣减为负 | 积分 |
| `balance_recharge` | 会员充值 | 正数 | 元 |
| `balance_grant` | 储值赠送 | 正数 | 元 |
| `balance_consume` | 储值消费 | 负数 | 元 |
| `balance_refund` | 储值退款 | 按资产余额实际变化保留正负 | 元 |
| `balance_adjust` | 其他储值调整 | 增加为正，扣减为负 | 元 |

## 后续积分爬虫接入时需要确认

1. 源平台是否能提供稳定的流水号、发生时间、门店、会员标识和变更后余额。
2. 源平台的退款符号和积分兑换符号是否与本契约一致；适配器负责统一成上述方向。
3. 爬虫是全量拉取还是增量拉取；建议保存平台游标，同时用幂等键兜底。
4. 会员标识只用于内部追踪。页面接口始终脱敏，原始数据的访问权限需要与现有凭证策略一起确认。
5. 真实业务阈值确定后，将当前大额提醒规则改为配置项，并补充告警确认、处理人和处理状态。
